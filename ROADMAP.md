# Status & roadmap

## Current state (verified on one machine)

Environment: macOS 27.2.1 (arm64), Python 3.9.6, CLI `trialreset`.

| Adapter | App version | Trial model | reset | launch | watch | block | Verified |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `crossover` | 26.3 | timestamps (`FirstRunDate`, `SULastCheckTime`) | ✅ | ✅ | ✅ | n/a (no endpoints) | reset + launcher + watcher |
| `parallels` | 27.0.3 | licence blob (`License.*`, `WiConfig`) | ✅ | ✅ | ✅ | ✅ (`account/my/licensing/activation/pcs`) | reset + launcher + watcher + hosts block |

Evidence collected during development:

- CrossOver: shifting dates back 3h makes the client treat the trial as fresh; the watcher fires
  because CrossOver writes prefs at launch.
- Parallels: deleting `License.*` / `WiConfig` and clearing `~/Library/Preferences/Parallels/*`
  returns the client to first-run (`WiConfig.mode = trial`); `License.*` is regenerated by the
  client on next start with the same constants, i.e. trial *type* is local, while the countdown
  *may* be server-assisted (unconfirmed).
- Hosts blocking makes `account.parallels.com` resolve to `0.0.0.0`; `curl` fails, Parallels still
  starts and stays in trial flow.
- WatchPaths fires on plist writes; the agent is configured to skip while the app runs, otherwise
  it would kill live sessions.

## Known gaps

1. **Parallels server-side verdict** — not confirmed either way. If the vendor returns "expired",
   clearing local keys will not change it; blocking only prevents the verdict from being cached.
2. **Trial clock provenance** — for Parallels we know *which keys* exist, not which field encodes
   elapsed days. `License.Params.*` stays constant across resets, so the clock is elsewhere
   (possibly account-bound).
3. **CrossOver update path** — assumes Sparkle replaces the app in place; if a future version
   moves state out of `com.codeweavers.CrossOver`, the adapter needs a new spec.
4. **No restore command yet** — backups exist under `~/.trialreset/<key>/backup/` but restoring is
   manual.
5. **Single-machine verification** — adapters tested on one macOS build.

## Roadmap

Near term

- `trialreset restore <app> [--date]` to roll back from the daily backup.
- `trialreset diff <app>` — before/after snapshot, so an agent can prove what changed.
- Schema auto-detection: when the dry-run plan is empty, scan the domain and suggest candidate
  keys (`trial|licen|firstrun|lastcheck|expire`) instead of only warning.
- Watcher guard configurable per adapter (current skip-while-running is hard-coded for all).

Mid term

- More adapters (any macOS app with a timestamp or blob trial): the spec is ~15 lines.
- Endpoint discovery helper: `trialreset net <app>` that records connections during a launch
  (`lsof` sampling) to populate `domains`.
- Optional PF rule generation for hard-coded IPs (the documented escalation after hosts).

Long term

- Portable host layer: preferences abstraction for Linux/Windows (registry / JSON / files) so the
  same adapter concept works beyond macOS. The planner (`plan_reset`) is already pure Python and
  platform-free; only the apply layer is macOS-specific.
- Structured evidence bundles: export backup + plan + check output as a tarball for bug reports.

## When the vendor changes something

1. `trialreset --json check <key>` — see which keys still exist.
2. `trialreset --json reset <key> --dry-run` — empty plan means the schema moved.
3. `defaults read <domain> | grep -Ei 'trial|licen|firstrun|lastcheck|expire'` — find the new keys.
4. Update the adapter spec, add a unit test with a synthetic snapshot, bump the documented
   `Verified` version in this file.
5. If the app now requires online validation, move to the network layer (`block`) and record the
   endpoints in the adapter.
